## Open Questions

> [!IMPORTANT]
> **1. Extracting `project_id` — from `_links` or `_embedded`?**
> The OpenProject memberships API response provides the project in `_links.project.href` (e.g. `"/api/v3/projects/5"`) and `_links.project.title` (e.g. `"Demo Project"`). I plan to:
> - Extract `project_id` by parsing the integer from the `href` string (`/api/v3/projects/5` → `5`)
> - Extract `project_name` from `_links.project.title`
>
> This avoids needing a separate API call per membership. Are you fine with this approach?

> [!IMPORTANT]
> **2. Dataclass vs Pydantic model for `Membership`?**
> The sprint spec says "Define a `Membership` dataclass". I'll use a plain Python `dataclass` (from `dataclasses`) as specified, not a Pydantic `BaseModel`. This keeps the data layer lightweight and framework-agnostic. Confirming this is what you want?

> [!IMPORTANT]
> **3. `role_ids` extraction — from `_links.roles` or `_embedded.roles`?**
> Each membership element includes roles in two places:
> - `_links.roles` — array of `{"href": "/api/v3/roles/3", "title": "Member"}`
> - `_embedded.roles` — array of `{"_type": "Role", "id": 3, "name": "Member"}`
>
> I plan to extract `role_ids` from `_embedded.roles[].id` since it gives us the integer directly without href parsing. If `_embedded.roles` is absent (edge case), fall back to parsing `_links.roles[].href`. Sound good?

## OpenProject API Reference

### `GET /api/v3/memberships` with user filter

**Request:**
```
GET /api/v3/memberships?filters=[{"principal":{"operator":"=","values":["14"]}}]
```

**Response structure** (confirmed from [membership_representer.rb](file:///home/iosamaayaz/Coding/FYP Stuff/openproject-private-clean/lib/api/v3/memberships/membership_representer.rb)):
```json
{
  "_type": "Collection",
  "total": 2,
  "count": 2,
  "_embedded": {
    "elements": [
      {
        "_type": "Membership",
        "id": 42,
        "_links": {
          "project": {
            "href": "/api/v3/projects/5",
            "title": "Demo Project"
          },
          "roles": [
            { "href": "/api/v3/roles/3", "title": "Member" }
          ]
        },
        "_embedded": {
          "roles": [
            { "_type": "Role", "id": 3, "name": "Member" }
          ]
        }
      }
    ]
  }
}
```

Key observation: The `associated_resources :roles` macro (line 75 of the representer) embeds the full role objects in `_embedded.roles` *and* provides link references in `_links.roles`. We can reliably use `_embedded.roles` for role IDs.

## Proposed Changes

### Dataclass

#### [NEW] [permissions_service.py](file:///home/iosamaayaz/Coding/FYP Stuff/openproject-private-clean/adaptive_ui_service/app/services/permissions_service.py)

This file houses both the `Membership` dataclass and the `get_user_memberships` function. Keeping the dataclass co-located with its service (rather than in `app/models/`) because:
- The sprint spec explicitly says "Continue in `app/services/permissions_service.py`" for T1.5
- A separate models file would add indirection for a single small dataclass

```python
import json
from dataclasses import dataclass

from adaptive_ui_service.app.core.openproject_client import OpenProjectClient


@dataclass
class Membership:
    project_id: int
    project_name: str
    role_ids: list[int]


def _extract_project_id(href: str) -> int:
    """Parse '/api/v3/projects/5' → 5"""
    return int(href.rstrip("/").split("/")[-1])


def _extract_role_ids(element: dict) -> list[int]:
    """Extract role IDs from _embedded.roles, falling back to _links.roles href parsing."""
    embedded_roles = element.get("_embedded", {}).get("roles", [])
    if embedded_roles:
        return [role["id"] for role in embedded_roles]

    link_roles = element.get("_links", {}).get("roles", [])
    return [_extract_project_id(role["href"]) for role in link_roles]


async def get_user_memberships(
    user_id: int, client: OpenProjectClient
) -> list[Membership]:
    filters = json.dumps(
        [{"principal": {"operator": "=", "values": [str(user_id)]}}]
    )
    data = await client.get("/api/v3/memberships", params={"filters": filters})

    elements = data.get("_embedded", {}).get("elements", [])

    memberships = []
    for element in elements:
        project_link = element["_links"]["project"]
        memberships.append(
            Membership(
                project_id=_extract_project_id(project_link["href"]),
                project_name=project_link.get("title", ""),
                role_ids=_extract_role_ids(element),
            )
        )
    return memberships
```

**Design decisions:**

| Decision | Rationale |
|---|---|
| `_extract_project_id` as a private helper | Reusable for both project href and role href parsing; will be needed again in T1.5 |
| `_extract_role_ids` tries `_embedded` first | Avoids string parsing when structured data is available |
| `json.dumps` for filters param | The OpenProject API expects JSON-encoded filter arrays as a query string value |
| Function takes `client` as parameter | Keeps the service stateless and testable — the caller controls the client lifecycle |
| No pagination handling | The spec doesn't mention it. A user's memberships are typically a small set (< 100). Can be added later if needed |
